# PDFテキスト変換ツール OCR版2（完全ローカル版）

## 起動方法

最上位の `PDFテキスト変換ツール_OCR版2_完全ローカル版.html` をダブルクリックしてください。Webサーバーやインターネット接続は不要です。

## OCRとTXT出力の操作

1. PDFを選択すると、OCRを起動せず本文だけを自動変換します。この時点のTXTには `【書誌事項】` 欄がありません。
2. 書誌事項が必要な場合は「書誌事項OCR読取」を押します。OCR完了後、TXT出力は書誌事項付きへ自動的に切り替わります。
3. 「TXT出力に書誌事項を含める」のチェックを外すと、OCR結果を保持したまま本文だけのTXTへ戻ります。再度チェックすれば書誌事項付きへ戻せます。

出力形式の切替だけではOCRを再実行しません。別のPDFを選択すると、再びOCR未実行・本文のみの状態から開始します。
「書誌事項OCR読取」ボタンとTXT出力チェックは、関連する操作として同じ操作枠内に左右に並べています。
OCR実行中はボタンが「OCR読取中…」、完了後は緑色の「✓ 書誌事項OCR読取済み」に変わります。失敗時は「OCR読取を再試行」と表示されます。新しいPDFを選ぶと未読取表示へ戻ります。

## 旧2段組公報と番号の確認

- 2段組の旧形式公報を検出した場合、存在しないテーマコードはOCRせず、Fタームも補完・出力しません。
- 登録番号は `特許第`＋数字7桁＋`号` を正常形式とします。
- 公開番号は `特開平`＋1～2桁＋`-`＋1～6桁、または `特開`＋4桁＋`-`＋1～6桁を正常形式とします。
- 出願番号は `特願`（必要に応じて平・昭）＋1～2桁＋`-`＋1～6桁、または `特願`＋4桁＋`-`＋1～6桁を正常形式とします。
- 数字欄の `O`、`I`、`L`、`S`、`B`は、数字として一意に判断できる場合に限り補正します。桁数超過やハイフン欠落など、一意に補正できない値には `（要確認）` を付けます。
- 2ページ目以降の公報ヘッダーから正常形式の公開番号・登録番号を取得できた場合は、OCRの不自然な値よりヘッダー値を優先します。
- OCR書誌全文は項目コードと項目名で区切って解析します。たとえば `(21)出願番号` の値は、次の `(22)出願日`、`(43)公開日`、`(65)公開番号`、`(71)出願人`、`(72)発明者`、`(73)特許権者`、`(74)代理人`などの直前で終了します。これにより、`特願平8-12095073特許権者`を`特願平8-120950`と`(73)特許権者`へ分離します。

## `blob:null` OCRエラーへの修正

`file://`で起動するとBlob URLのオリジンが `blob:null/...` になります。従来版ではOCR Workerから、別のBlob URLにしたTesseract Coreを `importScripts()` で読み込んでいたため、ブラウザーによって次のエラーで停止していました。

`Failed to execute 'importScripts' on 'WorkerGlobalScope'`

本修正版では次のように変更しています。

- Tesseract CoreをOCR Workerと同じ1個のBlobへ直接内包
- Tesseract Coreを読み込む `importScripts()` 呼出を無効化
- Tesseract.js標準の `jpn+eng` 初期化手順を使用
- OCR Worker自身が同梱学習データをメモリから読み込み
- 学習データの読込先を内部専用の `offline-tessdata://local/` に限定
- 内部専用URL以外へのOCR Workerの通信要求を遮断
- OCR失敗時は処理ログ、OCR生データ欄、変換結果の「OCR状態」にエラーを表示

## 同梱ライブラリ（固定バージョン）

- PDF.js 3.11.174
- Tesseract.js 5.1.1
- tesseract.js-core 5.1.1
- Tesseract日本語・英語学習データ 4.0.0

ライセンス本文は `local_assets/licenses` にあります。

## 確認用サンプル

`local_assets/sample/動作確認用_特許公報サンプル.pdf` を同梱しています。本文変換後に「書誌事項OCR読取」を押すと、少なくとも分類コード `A47J` を含む結果になることを確認用の目安にできます。

## 問題が残る場合

変換結果の「OCR状態」または「OCRで認識した生データ」に表示されるエラー全文と、使用したブラウザー名・バージョンを控えてください。初回OCRは学習データとCoreをメモリ展開するため、端末によっては開始まで時間がかかります。
